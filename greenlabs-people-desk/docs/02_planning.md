# 기획서 — 그린랩스 피플 데스크

## 1. 한 줄 정의
피플팀이 **메일을 뒤지지 않고** 채용 진행 상황과 다음 할 일을 한 화면에서 보고, 직원의 반복 질문은 **근거 문서와 함께** 자동으로 답하는 사내 채용·HR 데스크.

## 2. 목표와 성공 기준

| 목표 | 성공 기준 (고객 말 기반) | 측정 |
|---|---|---|
| 진행 상황 확인 시간 감소 | 지원자의 단계와 다음 담당자가 바로 보임 (Q33) | 보드에서 지원자 1명 상태 확인까지 클릭 1회 |
| 지원서 입력 수작업 감소 | 몰리는 날 오전을 통째로 쓰지 않음 (Q25) | 지원서 1건 등록: 수기 입력 → 붙여 넣기 + 승인 1회 |
| 안내 지연 방지 | 불합격 안내 5영업일 원칙 준수 (Q12) | 기한 초과 건이 대시보드에 0건이 되도록 알림 |
| 반복 질문 대응 | 규정집에 있는 질문은 피플팀을 거치지 않음 (이 매니저) | 질문에 근거(문서·조항·쪽)와 함께 답변, 민감 질문은 100% 이관 |

## 3. 사용자와 사용 장면

| 사용자 | 언제 | 왜 | 장면 |
|---|---|---|---|
| **피플팀 매니저 (서 매니저)** | 월요일 아침, 지원서 70통이 쌓였을 때 | 지원서를 빠르게 등록하고 진행을 놓치지 않으려고 | 지원서 메일 내용을 붙여 넣음 → AI가 이름·연락처·지원 경로·포지션을 채운 "등록 대기" 목록 확인 → 같은 이메일 지원 기록 확인 → 승인. 보드에서 "안내 기한 임박" 배지를 보고 불합격 메일 초안 확인 후 발송 처리 |
| **피플팀장** | 주간 채용 점검 | 어디서 막히는지 보려고 | 통계에서 포지션별 앞 단계 대비 통과율과 채용 사이트별 서류 통과율·면접 진출·입사 수 확인 |
| **면접관 (개발팀장)** | 면접 일정을 잡을 때, 면접 직후 | 일정 메일 10번을 없애고, 정해진 기준으로 평가하려고 | 가능 시간을 화면에 입력. 면접 후 포지션 기준표대로 점수·근거 입력·제출 → 그다음에야 다른 면접관 평가가 보임. 자기 포지션 지원자만 보임 |
| **직원 (입사 첫 주 신입 포함)** | 휴가·경비·재택이 궁금할 때 | 규정집을 뒤지지 않고 바로 답을 얻으려고 | "출장 택시비 한도?" → "1회 30,000원 · 사내 규정집 제16조 · 7쪽 (경비 지침은 40,000원이지만 개정일이 더 최근인 규정집을 따름)". "육아휴직 쓰면 연차는?" → 근거와 함께 답변. 건강 사정이 섞인 질문 → "피플팀이 직접 답드립니다"로 이관 |

## 4. 오늘 만들 기능과 미룰 기능

### 4-1. 오늘 만들 기능

| # | 기능 | 요구사항 | 정한 이유 |
|---|---|---|---|
| F1 | 지원자 데이터 가져오기 (엑셀 400명) + 누락 행 "확인 필요" | R15 | 진행 중 지원자를 이어서 봐야 함(Q29). 모든 기능의 바탕 |
| F2 | **채용 보드**: 포지션별 단계 칸, 다음 할 일·다음 담당자, 배지(안내 기한·과제 기한 초과·평가 미제출·중복·확인 필요) | R1, R2, R11, R16, R17 | 고객이 꼽은 성공 기준(Q33)과 가장 급한 문제(Q1) |
| F3 | 지원자 상세 + 단계 이동 / 불합격 / 중도 이탈(사유) | R1, R10 | 결정은 피플팀만(Q23), 이탈을 불합격과 분리해야 통과율이 맞음(Q26) |
| F4 | 면접 평가 (포지션별 기준표, 제출 전 타인 비공개) | R3 | 기본 요구사항 2, 편향 방지(Q14) |
| F5 | 면접 일정 (면접관 가능 시간 입력 → 피플팀 확정) | R4 | 기본 요구사항 3, 공용 캘린더가 없음(Q2) |
| F6 | 통계 (앞 단계 대비/전체 대비 통과율, 사이트별 성과) | R9 | 기본 요구사항 7, 고객 승인(Q22) |
| F7 | **직원 질문 답변 (AI)** + 근거 위치 + 충돌 규칙 + 민감·무근거 이관 | R5, R7, R8 | 기본 요구사항 4, 고객이 이번 범위로 당김(F1) |
| F8 | 문서 업로드 (PDF + 개정일) → 즉시 반영 | R6 | 기본 요구사항 5, 재택 개정 사례 |
| F9 | **지원서 자동 입력 (AI)** → 등록 대기 → 피플팀 승인, 중복 이메일 표시 | R12, R13 | 고객이 말하지 않았던 가장 큰 수작업(Q25). 고객 승인(F2). **가산점 제안** |
| F10 | 메일 템플릿 5종 + 불합격 안내 초안, "발송 완료" 기록 | R14, R11 | 매번 새로 씀(서 매니저), 5영업일 원칙 |
| F11 | 역할별 로그인과 권한 (피플팀/면접관/직원) | 권한표 | 고객이 가장 여러 번 강조함(개발팀장, Q8, Q11, Q14, Q15) |

### 4-2. 미룰 기능

| 기능 | 미룬 이유 |
|---|---|
| 슬랙에서 질문하기 | 웹으로도 된다는 답(Q7), 고객 승인(Q24). 같은 답변 API를 슬랙 봇에 연결하면 됨 |
| 온보딩 요청 (노트북·계정) | 흐름이 정리돼 있지 않음, 고객 승인(Q20, Q24) |
| 실제 메일 발송 | 해커톤 환경에서 실제 발송은 위험. 초안 + 발송 완료 기록까지만 |
| 지원자가 면접 시간 직접 선택 | 면접관 일정 변경 시 혼선 우려(Q27) |
| 캘린더 연동 | 공용 캘린더 없음(Q2) |
| 채용 사이트 메일함 자동 수집 | 사이트별 형식이 다르고 계정 연동이 필요. 오늘은 붙여 넣기 방식 |
| 불합격자 자동 파기 | 보관 기간 미정(Q21). 기간 지난 지원자 "파기 대상" 표시까지만 구현(보관 기간은 설정값) |
| 평가 기준표 편집 화면 | 포지션별 기준표는 고객 엑셀에서 가져와 설정값으로 저장. 기준 변경은 드물어 다음 단계 |
| 엑셀 지원자 가져오기 화면 | 400명 이관은 1회성이라 시드로 처리. 이후 신규 지원은 지원서 자동 입력으로 등록 |
| 직원용 문서 원문 목록 | 답변마다 문서·조항·쪽을 보여 주는 것으로 대신. 원문 열람은 다음 단계 |

## 5. 가산점 제안 (고객이 직접 말하지 않았지만 필요한 기능)

| 제안 | 근거 | 구현 |
|---|---|---|
| **지원서 자동 입력 + 피플팀 확인** | 고충 장면(지원서 70통을 스프레드시트로 옮김), Q25 "오전이 지나감" | 구현 (F9) |
| **불합격 안내 5영업일 기한 알림** | Q12 내부 원칙, "탈락 안내를 제때 못 해 평판에 안 좋다" | 구현 (F2 배지, F10) |
| **문서 충돌 표시** | 문서 3종이 겹침 + 개정 반영 요구. 고객이 정한 규칙대로 답하되 다른 문서 내용도 알려 직원 혼선을 줄임 | 구현 (F7) |
| **불합격과 중도 이탈 분리** | 섞이면 통과율이 왜곡됨(Q26) | 구현 (F3, F6) |
| **평가 제출 기한 표시** | 평가 지연으로 결정이 밀림(Q28) | 구현 (F2 배지) |

## 6. 데모 시나리오 (10분 발표 중 5분)

1. 피플팀으로 로그인 → 보드: 백엔드 서류 71명, "안내 기한 초과 7건" 배지
2. 지원서 붙여 넣기 → AI가 채운 등록 대기 → "같은 이메일 지원 기록 있음" → 승인
3. 개발팀장으로 로그인 → P01·P02·P04만 보임 → 평가 제출 전 다른 평가 가려짐 → 제출 후 보임
4. 직원으로 로그인 (처음에는 구버전 규정집 2026-03-01이 올라가 있음) → "재택근무 주 몇 일?" → 주 2일 + 근거 / "아이가 아파서 병가 쓰려는데…" → 피플팀 이관
5. 피플팀이 규정집 개정판(2026-10-01) 업로드 → 같은 질문의 답이 주 3일로 바뀜 → "출장 택시비 한도?" → 30,000원 + 근거 + "경비 지침에는 40,000원이지만 개정일이 더 최근인 규정집을 따름" 표시
6. 통계: 앞 단계 대비 통과율에서 병목 확인
